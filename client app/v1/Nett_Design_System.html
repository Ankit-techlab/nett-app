NETT · DESIGN SYSTEM · FOR THE TEAM

Waterline.
Why the product looks like this.

This is the thinking, not just the tokens. Read it once end-to-end before designing a single new screen. The rule that governs everything else: the design system is the only source — nothing new without sign-off.

1 · The concept

NettNett

Wealth is water. It has a level. It rises, it drains, it leaks. Nett's one promise — "Grow what you own. Clear what you owe." — is a promise about where your line sits, so the entire visual language is built on one image: the waterline.

Direction C (the chosen identity): the wordmark's lower third sits submerged — refracted 3 units, water-toned, at 55% opacity. Above the line = what's surfaced, visible, yours to act on. Below the line = what's submerged — potential, or hidden until shared. This single metaphor then does real work everywhere:

· The depth gauge ("Your line") shows a score as a level, not a number in a box.
· The consent gate renders unshared data literally below the waterline — blurred, waiting.
· The vessel fills as the day's work completes.
· Views surface — they rise from below when they open.

Nothing in the UI is decorated with water. Things behave like water. That's the difference between a theme and an identity.

2 · Why dark, and how the colors were chosen

The color objective, stated plainly: money UIs usually shout — red/green tickers, badges, urgency. Nett's user is anxious about money already. The palette's job is to lower the heart rate and raise the signal. Every color decision followed four rules:

1. Dark is depth, not style. A near-black base (#0C0D10, never pure black) makes the interface feel like still water at night — calm, deep, focused. It also lets tiny amounts of color carry huge meaning.
2. One neutral family, three volumes. Text speaks at three loudnesses only — tx / mut / dim. If you need a fourth grey, the hierarchy is wrong, not the palette.
3. Color = state, never decoration. Green/amber/orange/red exist solely to mean GOOD / WATCH / ATTENTION / CRITICAL. A color used decoratively steals meaning from every state pill in the product.
4. Muted, warm, desaturated. Every accent is pulled back from its pure hue (green is #3ED598, not #00FF88) so states inform without alarming. Nothing neon. Ever.

The palette, token by token

--bg #0C0D10

Night water. Never #000 — pure black kills depth layering.

--tx #ECECF1 · --mut #8E8E9C · --dim #6B6B78

The three text volumes. Off-white, never #FFF — pure white glares on dark.

--bone #C9C3B2

The wordmark above the line, and the app-canon accent. Warm bone, not gold-bling: wealth as something aged and steady, not shiny.

--water #8FB2EE

Only for the submerged: the wordmark's lower third, deep-water surfaces. Never a text color.

--pos / --watch / --attn / --neg(--crit)

The four-band state system: GOOD · WATCH · ATTENTION · CRITICAL. These are semantic, product-wide, and locked to the Rule Book bands. Two hard rules travel with them: NO DATA must never look like a passing state, and ERROR must never look like NO DATA.

--lav #BDB3F6 — Arth only. No exceptions.

Lavender marks exactly one thing: Arth is speaking. Its power is its scarcity — the moment lavender appears on a pill or a chart, users stop knowing when the AI is talking. This rule has been violated once (stage pills, CRM v1.0) and is now audit-enforced.

--deep1 #152440 / --deep2 #0B1220

Deep-water ambients — background gradients only, never surfaces or text.

Open reconciliation (honest flag): the app canon aliases --gold → var(--bone) (#C9C3B2); the CRM carries an independent --gold #D9B96A. One of the two must win before dev handoff hardens it. Decision owner: founder. Until decided: new work uses bone as the accent, per app canon.

DisplaySerif (.ser — New York / Iowan / Georgia) for headline moments only: screen titles, Arth's big statements, numbers that deserve weight. Serif = the human, editorial voice.

4 · Do's & Don'ts

Do — reuse an existing component before drawing anything. The inventory: cards, rows, tags, pills, CTAs (solid/outline/ghost), fields, OTP boxes (6-digit), depth gauge, vessel, consent gate, waterline divider, moment cards, chat bubbles (.msg/.msg.arth), kanban, list table, sidebar shell, Arth rail.
Do — let every state color mean its band. If something is "highlighted" but has no state, it takes bone, at low opacity.
Do — show last-good data with its timestamp when something fails, with exactly one action: Retry. Every error carries a trace ID.
Do — write copy that carries a number or ends in an action. Both surfaces, no exceptions.
Don't — add a color, a font, a theme, or an icon set. There is no light theme in beta by decision. There is no second accent.
Don't — use lavender or the Arth mark anywhere Arth isn't speaking.
Don't — invent a "nicer" version of an existing element. The droplet-instead-of-waterline-mark and the gradient wordmark both happened, both were canon violations, both are now blocked by automated audit.
Don't — let NO DATA look green, or let an error look like NO DATA. One asks for consent; the other promises recovery.

5 · Governance — how change enters the system

When anyone (including leadership) asks for something that conflicts with this document, the answer is not "yes" and not "no" — it's the protocol:

1. Classify the request: reuse (build it) · variant of existing (build, note it) · genuinely new token/component/pattern (STOP).
2. Cross-check against this file + the UX Architecture. Name the exact principle it touches.
3. Confirm before acting: present the conflict, the options, and the impact (screens, flows, both surfaces). No silent changes — ever.
4. On approval: patch with assertions → run the audit → version bump all three artifacts together (design file · flow doc · release note, same number, latest on top, IST timestamp).
5. New canon (tokens, components, marks) gets written back into this document in the same release.

The audit is not optional ceremony — it has caught real regressions, wrong-file writes, and canon drift. If a check fails, the release doesn't ship.
